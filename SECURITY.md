# Безопасность и защита данных (Security Policy)

## Реализованные механизмы защиты:
1. **Аутентификация эндпоинтов (`api/check.js`)**:
   - Авторизация принимается **исключительно** через заголовок `Authorization: Bearer <CHECK_SECRET>`.
   - Поддержка передачи секретов через URL Query (`?secret=...`) отключена для предотвращения утечки ключей в Access-логи и историю браузера.
   - Сравнение токенов выполняется через `crypto.timingSafeEqual` для защиты от атак по времени (Timing Attacks).
2. **Экранирование HTML для Telegram**:
   - Все динамические поля (названия промо-акций, токены, таймеры, ссылки) экранируются через функцию `escapeHtml()` (`&`, `<`, `>`, `"`), что исключает инъекции и сбои Telegram API `400 Bad Request`.
3. **Безопасность GitHub Actions**:
   - Все входные параметры (`inputs`) и контекстные переменные (`github.event.*`) передаются в скрипты только через переменные окружения `env:`, предотвращая Command Injection.
4. **Изоляция данных в Redis**:
   - Все ключи состояний изолированы уникальными префиксами (`STATE_KEY`), предотвращая коллизии данных между ботами.
